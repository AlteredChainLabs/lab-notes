# 2026-07-28 --- MathLab v0.2: Socratic Tutor Prototype

## Goal

Begin development of MathLab v0.2, moving the AI Tutor from a simple
request-response assistant toward an adaptive Socratic tutoring system.

The central design principle is:

> Given the problem, the student's current work, and their previous
> assistance, choose the smallest intervention likely to produce
> meaningful progress.

------------------------------------------------------------------------

## Socratic Tutor Design

Before implementing the system, we simulated tutoring interactions
manually to identify what information and intervention types the tutor
actually needs.

Two problem-solving simulations suggested that tutoring should
distinguish between evaluating a student's reasoning and revealing
additional solution information.

### Learner states

Initial learner-state vocabulary:

-   `exploring`
-   `productive`
-   `stuck`
-   `misdirected`
-   `near_solution`

These states are intentionally coarse. More detailed learner modeling
can be added later if actual interactions show that it is useful.

### Tutor interventions

Initial intervention vocabulary:

-   `probe`
-   `affirm`
-   `feedback`
-   `clarify`
-   `example`
-   `recall`
-   `redirect`
-   `nudge`
-   `focus`
-   `key_idea`
-   `finish`

The simulations revealed that process interventions and solution
assistance should be treated differently.

Process interventions:

`AFFIRM`, `PROBE`, `FEEDBACK`, `CLARIFY`, `EXAMPLE`, `RECALL`,
`REDIRECT`

Solution assistance:

`NUDGE → FOCUS → KEY IDEA → FINISH`

The tutor should prefer process interventions whenever possible and
escalate through solution assistance only when necessary.

A student's request for a hint is treated as student intent, not as an
instruction that the tutor must reveal a hint.

## Tutor Context

Extended the MathLab tutoring pipeline so that the AI tutor now receives
information about the student's interaction with the existing hint
system.

Current pipeline:

`ProblemWorkspace → AITutor → /api/ai → Gemma 4 Cloud`

Tutor context currently includes:

-   current student attempt
-   requested help action
-   number of static hints already revealed
-   problem title and statement

`HintLadder` now reports its current reveal count to `ProblemWorkspace`,
which passes it to `AITutor` and ultimately to the AI API route.

Existing localStorage persistence for work, hints, and solutions was
preserved and tested successfully.

------------------------------------------------------------------------

## Structured Tutor Decisions

Reworked `/api/ai` so the model no longer generates only tutor prose.

Gemma now evaluates the learner and returns a structured pedagogical
decision:

``` json
{
  "learnerState": "productive",
  "intervention": "probe",
  "response": "..."
}
```

The API validates:

-   learner state
-   intervention type
-   tutor response

Invalid structured responses are rejected instead of silently accepting
malformed model output.

The frontend currently displays only the `response`, so the existing UI
remains unchanged while the new tutoring policy is tested.

## First Successful Test

Test problem:

> Prove that (2\^n + 1) is divisible by 3 infinitely often.

Student work explored several small cases modulo 3 and discovered the
alternating pattern.

Instead of revealing the general argument, the tutor responded:

> You've found a clear pattern for the first few values of n. Based on
> these examples, for which values of n does (2\^n + 1) seem to be
> divisible by 3?

This is the intended Socratic behavior.

The student's reasoning was already productive, so the tutor asked the
student to extract the next observation rather than supplying it.
